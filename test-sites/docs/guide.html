Writing a plugin

A Quillwork plugin is a JavaScript module with a default export: a function that receives the build context and may register one or more hooks. This guide builds a plugin that adds a reading-time estimate to every page.

Anatomy of a plugin

Plugins run in the order they are listed in the configuration file. Each receives a ctx object containing the resolved options, a logger and a registry of hooks. A plugin should do its work inside a hook rather than at load time, because at load time the pages have not yet been read.

export default function readingTime(ctx) {
  ctx.hooks.transform((page) => {
    const words = page.text.split(/\s+/).length;
    page.meta.minutes = Math.max(1, Math.round(words / 220));
    return page;
  });
}

Hooks

HookRunsReceives
readOnce per source fileRaw file contents
transformOnce per page, after parsingA page object
writeOnce per output fileThe final HTML string

Hooks may be asynchronous. Quillwork awaits each one before moving on, so a slow plugin slows the whole build; keep network calls out of the hot path where you can.

Testing plugins

Because a plugin is only a function, it can be tested without running a build. Construct a fake context, call the plugin, then call the registered hook with a sample page and assert on the result. This takes milliseconds and needs no files on disk, which is why the examples in this documentation are written the way they are.

History

The first release, in the autumn of a year that does not exist, supported a single input format and no plugins at all. Plugins arrived in version 1.2 after a contributor pointed out, with some justification, that everyone was forking the project to add one small feature each.
